## Local gateway and film pipeline

The Chinese version of this page carries the full detail. The authoritative ordering, dependencies and acceptance criteria are in §8 of `docs/content/docs/progress/development-plan.md`; the product-level priorities are in §6 of `prd.md`. Only not-yet-started items are listed here.

- **P0-a Fix the `artifactUrl` write-back break**: `attachGeneration` sets it to null and nothing in the repository ever assigns it again (the job queue has no callback into the pipeline), so the end frame never receives the start frame as a reference, `assembly` never enqueues, and `stage.artifacts` is always empty — **the five-stage pipeline is really four and a half and cannot reach a finished film**. The fix is to subscribe to the `jobs` change event and write the item back; `job.meta` already carries `{runId, stageId, itemId}`, so the reverse lookup is already possible. This is also the prerequisite for the swappable generation slot (same write-back path).
- **P0-b Make runs recoverable**: the frontend `run` is a bare `useState`, so a refresh loses it forever while the backend keeps running and keeps spending credits; the server **already has** `GET /api/pipeline/runs` but the frontend never wrapped it. Persist the runId, add the list client, allow naming (everything currently lands as "未命名流水线"), and add a leave-page guard.
- **P0-c Naming refactor + Project as a server-side entity**: rename `CanvasProject` to `Canvas`; the new `Project` entity is one drama and may contain several canvases. **This must happen before writing new code**, otherwise the ambiguity around `projectId` spreads (`CanvasAgentSnapshot.projectId` currently holds a canvas id).
- **P1-a Open up the pipeline's only exit**: `pages/pipeline/` has zero references to the asset/canvas stores, so outputs are a dead end and moving 30 shots × 2 frames onto the canvas costs 60 rounds of "save as + re-upload". Assets should reference server artifacts rather than copy a third time, and `shots[]` should import into the storyboard board in one click (the plugin's Shot type and the server's stage-02 contract share 11 identically named fields; today the only way is to copy the JSON and pay the LLM to redo the storyboard).
- **P1-b Swappable generation slots**: a re-run currently does `item.jobId = null` and destroys the previous output, so comparison is structurally impossible; `item.template` is hardwired to the global config and even `run.options.image.template` has no effect. Move to `candidates[] + selected` plus a regenerate endpoint that appends one candidate to one item.
- **P1-c Absorb the six-stage methodology**: add stage 0 (planning and parameter clarification), pour the craft methodology into each stage's prompt-template section while keeping the output contracts. Bound by the content-authoring policy in `AGENTS.md`: faithful to the source, no didactic structure injected, flag review risks but never rewrite, review personas demoted to advisors. Also wire up the two libraries in `skills/libraries/` (script-writing-studio and the Luster aesthetic library) — the style-anchor mechanism is exactly the hook that connects Luster.
- Give the clip-assembly stage an ffmpeg concatenation executor: `assembly` only plans the clips and their order; there is no concat/transition executor, no video upscaling, and no audio muxing. Local ffmpeg is enough and does not touch the GPU. **Note this is a different problem from P0-a**: P0-a is that the keyframes never arrive so nothing is enqueued, this one is that even with clips produced there is no executor to concatenate them.
- Speed up video: measure the upstream `video_h3_i2v_sla` / `video_h3_i2v_blockcache` acceleration templates; rendering drafts at lower resolution and only the final pass at full size needs no new model and no new template.
- Add a `schema` to `TemplateInfo`: upgrade `tokens: string[]` into a typed schema with ranges, defaults, and frame-grid constraints so that "drop in a workflow JSON and it just works" holds, and delete the frontend branches keyed on template names.
- Generation-job observability: connect the ComfyUI WebSocket for real progress (a job's `progress` currently only ever reports 0/0) and expose it as `GET /api/jobs/:id/events` (SSE) plus `?wait=` long polling. Video jobs take 8–40 minutes. (Pipeline **stage** progress was finished in the previous round; this item is about **generation job** progress.)
- Verify RunningHub against the real service: the adapter is complete but the old API key is dead, so submit / query / upload still need a valid key; the frontend also has no backend-switching entry point yet.
- Snap `img_` template sizes to multiples of 32: Qwen-Image 2.1 officially recommends multiples of 32, but the gateway's snapping currently only applies to the `video_` prefix (`generate.js`).
- Dead fields in the frozen contract: `comfy.maxQueue` (default 16, never read anywhere in `src/`) and the job's `progress` (only ever 0/0, no ComfyUI WebSocket). Either implement them or drop them from the contract — do not keep promising fields that do nothing.
- Converge duplicated implementations: text-file import is duplicated verbatim twice, `type="file"` appears in 11 places, the model dropdown has 3 implementations, "provider::model" has 2 encodings, sizes use 3 vocabularies, and "save to asset library" is written 7 separate times. Low-cost but high-frequency friction — fold it into the P0/P1 work rather than spending a round on it.
