## 0. 这份文档回答什么（给审阅者的背景）

一个正在开发的**本地化 AI 短剧生产平台**（`/sobey/canvas-plus`）：Node 零依赖网关 + React 前端 + 本地 ComfyUI 出图出视频 + 可选本地/云端 LLM 文本链路，七阶段流水线（剧本 → 分镜 → 视觉资产 → 角色定妆 → 关键帧 → 音频 → 片段合成），面向海外发行；图像、视频、音频与私有素材不出本机，文本和提示词改写可按项目策略使用云端 LLM。

**产品负责人提出的命题**（本方案要回应它）：

> 「我认为现有的开发计划容易走向一个误区，就是**网页上实现所有短剧生产的功能，其实这个是做不到的**。」

**本方案的结论**：这个判断是对的，而且**有硬证据**。但「做不到」不等于「放弃」——正确的动作是**重划边界**：网页负责把生产做到「能被专业剪辑接手」，最后一公里的精剪交剪映/达芬奇。下面给出证据、边界划分、开源选型与分期方案。

---

## 1. 结论先行（一页）

1. **网页不是做不了，而是不该做「全部」。** 行业头部（LibTV）、同类开源（LocalMiniDrama）、甚至 91k star 的网页剪辑器（OpenCut），**都没有把精剪做进网页**。
2. **真正的达标线是「粗剪 + 自动装配 + 导出交换格式」**，而不是「站内精剪」。行业对比评测把「画布内置剪辑链路、**可粗剪后导出达芬奇**」列为达标，「视频生成后需自行处理、**无自动成片装配**」列为不达标。
3. **我们缺的恰好是这三段**（不是缺剪映）：**① 自动粗剪装配 ② 片头/文字动效包装 ③ 导出标准素材包**。
4. **精剪（卡点、节奏、多轨、调色）永远交剪映/达芬奇。** 这是行业通行分工。
5. **开源可融合清单已就绪**（含**商用许可证红黑榜**）：字幕用 FunASR、TTS 可换 CosyVoice2/GPT-SoVITS、数字人用 MuseTalk、音效用 ACE-Step；**编排不要搬进网页**（沿用 ComfyUI workflow JSON + 自研网关）。
6. **下一步先做三件事让「网页 → 剪映」这条路真通**（详见 §6）。

## 2. 四条独立证据：为什么「网页做全部」是误区

### 证据 1 — LibTV（商业标杆）：官方流程终点就是剪映

- LibTV 官方教程标题即：「手把手 **LibTV + Seedance 2.5 + 即梦 + 剪映**」。
- 我们把它**全部页面路由**翻过一遍（`libtv-product-analysis.md` §2.2，实测 HTTP 状态码）：**没有任何一条剪辑 / 时间线 / 精剪路由**。
- 它的「Director Studio」名字像剪辑台，实际是**生成参数预设面板**（叙事/视觉/拍摄三维度 + 风格预设）。
- 它的剪辑能力收敛为 1.5 版新增的**「创意片头」**：片名 + 文字动效 + **字幕识别与样式调整** + **口播场景的自动粗剪 / 画中画 / B-Roll / 音效配乐**。**是粗剪与包装，不是精剪。**

### 证据 2 — LocalMiniDrama（同类开源，最接近我们）：成熟到 2.4 万行，仍然没做剪辑

`xuanyustudio/LocalMiniDrama`：MIT、Vue3 + Node + Electron、**22 次数据库迁移**、约 **24k 行**、1.6k star，号称「剧本 → 角色/场景 → 分镜 → 视频合成」全流程。调研结论：

- **没有内置编辑器 / 时间线 / 精剪**（功能面上不存在）。
- 它的「成片」= `ffmpeg -f concat -safe 0 -c copy`，即**原始流拷贝拼接**：无转场、无裁剪、无变速、无重排、无多集处理。
- **没有剪映草稿导出**（全仓 grep 零命中）—— 而它是个 Windows 桌面应用，「桥到剪映」本该是最自然的出口。
- ⚠️ **一个我们必须避开的反面教训**：它的 ffmpeg 拼接**失败时会静默回退到第一段片段，并且仍然把任务标记为 `completed`**。这是「静默降级」，我们在自己的实现中明确禁止（缺段必须显式报出）。
- 音频侧：TTS 仅两家（MiniMax T2A + OpenAI 兼容 `/audio/speech`）；字幕仅旁白自动 SRT，且**字幕时间轴用「分镜声明时长」估算，未与语音对齐**；无 BGM / 音效 / 口型 / 字幕编辑器。

**反向推论**：一个**专门做短剧、已经迭代到 22 次迁移**的项目，仍然没把最后一公里做进网页 —— 这不是「能力不够」，是**分工共识**。

### 证据 3 — OpenCut（「开源剪映」，91k star）：网页剪辑器自己也卡住了

- **新版**（Rust 重写）：编辑器路由内容就是 `"Coming soon."`；API 只有 `/health` + `/echo` 骨架。README 把 **Editor API / 插件架构 / MCP server / headless mode / 脚本标签页**全部列为 coming。
- **classic 版**（线上跑的）：Next.js + React + Rust→WASM，可 Docker 自托管，但 README 明确 **archived / no longer maintained**（末次提交 2026-05-17）。
- **格式能力**：**无 FCPXML、无 EDL、无 OTIO**（全仓 grep = 0）；导入仅 SRT + ASS，**字幕不能导出**；导出只有 MP4/WebM 且 **100% 在浏览器内完成**；项目数据存**浏览器 IndexedDB + OPFS，无服务端项目 API**；无中文 UI。

**反向推论**：连 91k star 的网页剪辑器，做了一年仍停在「纯浏览器剪辑」，并把 API/headless/MCP 列为「重写才能有」的未来项 —— 这本身就是「网页别试图包揽全流程」的最强背书。

### 证据 4 — 行业达标线（第三方对比评测）

一份对市面 AI 短剧工具的横向评测给出的能力分档：

- **达标**：「Agent **自动完成剪辑、字幕、成片组装**」「画布内置剪辑链路，**可粗剪后导出达芬奇**」
- **不达标**：「视频生成后需自行处理，**无自动成片装配**」

**达标线是「粗剪 + 导出」，不是「站内精剪」。**

## 4. 边界重定义（本方案核心）

### 4.1 分工表

| 环节 | 谁做 | 理由 |
| --- | --- | --- |
| 小说/剧本/分镜/服化道/关键帧/片段生成 | **网页** | 已具备，且是本平台的核心价值 |
| **自动粗剪装配**（按分镜顺序拼、转场、字幕轨） | **网页** | 可完全自动化；不做则剪辑师要手工对 17 段素材 |
| **字幕识别与烧录** | **网页**（用 FunASR 字级时间戳） | 自动化程度高 |
| **片头 / 片名 / 文字动效** | **网页** | 模板化，成本低，出片质感关键 |
| **封面 / 分集打包 / 导出交换格式** | **网页** | 交付必需 |
| **音效 / BGM** | **网页**（ACE-Step 生成）+ 可手调 | 可作为音频轨写入导出包 |
| **精剪：卡点、节奏微调** | **剪映 / 达芬奇** | 人的审美，无法自动化 |
| **多轨混音精调、复杂转场、特效** | **剪映 / 达芬奇** | 专业工具强项 |
| **调色、风格统一、反复试看** | **剪映 / 达芬奇** | 同上 |
| 数字人 / 换口型（可选增强） | **网页**（H3 Talk / MuseTalk / LatentSync） | 16GB 可跑，需错峰；默认成片不依赖口型通过 |

### 4.2 判据（一句话）

> **凡是「有确定规则、可枚举、错了能被程序发现」的步骤 → 网页做。**
> **凡是「依赖人的判断、需要来回试、没有唯一正确答案」的步骤 → 交专业工具。**

### 4.4 并列原则：**模型适配是后端的职责，不是用户的负担**（2026-10-03 产品负责人提出）

> 原话：「用户不需要关心这些细节，用户只需要关心内容是否合理，但是你作为 CTO 需要关注这个内容，也就是说，**不论用户在前端如何配置如何调整情节，它选择了模型发起了这个生成请求的时候，图片生成还是视频生成都应该要按照对应模型的要求和标准写相关的提示词，然后再发给模型接口**，才是后端的真正存在的意义」

**工程约束（三条）**：
1. **内容层只产出「模型无关的内容事实」** —— 分镜/剧本**不得产出任何模型专属提示词**。理由：用户随时可能换模型（H3 / Wan / Kling / Qwen-Image / …），把某个模型的提示词烧进内容层，换模型即报废。
2. **后端必须在「发起生成请求」那一刻编译提示词** —— 只有那时才知道**选了哪个模型** + **本次实际注入了哪些素材槽**（首帧/尾帧/参考图）。所以这活儿天生属于后端。
3. **图片生成与视频生成一视同仁** —— 都要按各自模型的要求与标准写。

**落地形态：后端「提示词编译器」**（不是"在分镜里多写一个字段"）
```
内容事实（action / cameraSpec / dialogue / audio / textOverlays / shotSize / durationSec）
        ↓
后端编译器 —— 按所选模型分派
   H3 系（video）        → 官方三段式中文（参考素材说明 + 核心创意 + 画面过程说明）
   Qwen-Image 2.1（img） → 按其规范（中文利于文字渲染 / `<imageN>` 引用 / 透明背景 RGBA 句式）
   其它模型              → 通用兜底（不得退化）
        ↓
连同「本次实际注入的槽位」一起 → 发给模型接口 / ComfyUI
```
⚠️ **「参考素材说明」段的编号必须由编译器按实际注入顺序生成** —— 上传顺序由流水线决定（首帧→尾帧→角色参考→场景参考），写在内容层必然对不上。

**对原计划的影响（重要修正）**：本方案早期设想「在分镜阶段新增 `h3Prompt` 字段」，**该做法已被本原则取代** —— 分镜只出模型无关事实，模型专属提示词交给后端编译器。相关台账条目见 `pilot-issues.md` #53。

### 4.3 这条边界的一个直接推论

**我们不需要做时间线编辑器。** 那是最贵、最难、最容易被专业工具碾压的一块（OpenCut 91k star 都还在"Coming soon"）。我们要做的是**把素材整理到专业工具能直接接手**：排好序、带字幕、带命名、带清单。

## 5. 开源融合选型（调研结论）

原始调研：`research/03-oss-toolchain.md`（含 40+ 仓库的星数/活跃度/许可证一手数据）。

### 5.1 商用许可证红黑榜（产品负责人明确在意）

**✅ 可放心商用**：`auto-editor`(Unlicense)、`FunASR`(MIT)、whisper 系、`CosyVoice2`(Apache-2.0)、`GPT-SoVITS`(MIT)、`F5-TTS`、`MuseTalk`(MIT)、`LatentSync`(Apache-2.0)、`SadTalker`、`ACE-Step`(Apache-2.0，**含权重**)、`NarratoAI`(MIT)、`LocalMiniDrama`(MIT)、`OpenCut`(MIT)

**❌ 商用红线（避开）**：
- `IndexTTS`（bilibili 自有许可，有商用限制）
- `Fish-Speech`（需商业授权）
- `ChatTTS`（**AGPL**）
- **`MusicGen` 的模型权重是 CC-BY-NC**（⚠️ 仓库代码是 MIT，极易误判 —— 只能非商用）
- `Wav2Lip`（**无许可证 + 仅学术用途**）

### 5.2 分环节建议

| 环节 | 建议 | 融合成本 |
| --- | --- | --- |
| **中文字幕 ASR** | **`FunASR`**（MIT，**字级时间戳 + 说话人分离**，中文效果最好）；备选 `WhisperX`(BSD-2) | 中：需起服务 + 打通音频输入 |
| **字幕样式** | **ASS 模板 + libass**（ffmpeg 已支持），不自研样式编辑器 | 低 |
| **TTS / 声音克隆** | 现有 **Qwen3-TTS 已可用**；若要更强音色一致性/情感 → `CosyVoice2`(Apache-2.0) 或 `GPT-SoVITS`(MIT) | 中：换服务，接口已抽象（`audio.js` 的 `buildTtsRequest`） |
| **数字人 / 换口型**（可选） | **`MuseTalk`**(MIT，轻量) 首选；`LatentSync`(Apache-2.0) 高质量 | 高：需与 ComfyUI 错峰抢 16GB 显存 |
| **音效 / BGM** | **`ACE-Step`**(Apache-2.0 含权重) | 中 |
| **粗剪辅助** | `auto-editor`(Unlicense) 用于**去停顿 / 按静音切分**（口播类） | 低 |
| **动效** | `Motion Canvas`(MIT) 用于片头/文字动效；⚠️ **`Remotion` 商用需付费** | 低-中 |
| **工作流编排** | **结论：不要把编排搬进网页** —— 沿用「ComfyUI workflow JSON + 自研 Node 网关」。要画布式参考可看 `Langflow`(MIT) | — |
| **短剧垂直参考** | `NarratoAI`(MIT) 的「解说文案 → 自动成片」管线值得借鉴（解说类短剧） | — |

### 5.3 硬件约束（必须写进方案）

**147 机器 16GB 显存是全局瓶颈**：`ComfyUI`（出图/出视频）与**数字人模型**会**争抢显存**，必须**错峰调度或显存锁**。
- ✅ 16GB 可跑：ASR / TTS / 多数数字人 / 音效
- ⚠️ 贴边（需串行）：`LatentSync` / `EchoMimic` / `Hallo` / `YuE`
- ❌ 跑不动：`SkyReels-V2 14B` / 混元 / `Open-Sora`

| 3 | **跑通一部完整成片** | ⬜ | 17 镜全部出片段 → 粗剪成一集 → 导出素材包 → **真在剪映里导入验证一次** |
| 4 | TTS 接进流水线阶段 | ⬜ | 音频成为阶段产物（有 Job、Cue 落库、可追溯）|

**期一完成即达成「生产闭环」**：从小说到「能在剪映里打开的时间线」。
