# H3 成片声音与声画质量审计（2026-10-06）

## 结论

当前流水线已经具备“剧本 → 分镜 → 资产 → 定妆 → 关键帧 → 配音 → 片段 → ffmpeg 成片”的可运行闭环，但 **M6 只证明了任务和文件能够完成，不等于声音与声画质量验收通过**。用户反馈的三类问题（跨镜音色不稳定、电话场景抢台词、嘴型与语音不同步）与现有代码的结构性缺口一致，暂时不能归咎于 MiniMax H3 模型本身。

本审计基于当前代码、技能契约、M6 记录、音频/交付测试，以及本轮独立 CDP 页面验收。没有拿到用户所说的两段原始文件和波形报告，因此下列根因按“代码已证实 / 高概率 / 待真机复现”区分。

## 根因定位

### 1. 音色前后不一致：事实源没有在生成入口收敛

历史样片的项目计划是 `separate_dialogue_track`，但生成时仍把 `<d>` 台词交给 H3，成片又混入独立 TTS。首轮修复已把项目音频路线传给 H3 编译器，并在独立对白模式移除 `<d>`；缺失 TTS 会保留质量阻断信息，不再静默切换为 H3 人声。历史产物必须重跑才能获得新语义。

结论：必须在**生成入口**决定一条声音路线，并把路线写入 run/manifest：

- `embedded`：使用 `video_h3_talk` 或 H3 原生音频，声音和画面同一次生成，允许作为单镜增强；不能再混入独立 TTS。
- `separate_dialogue_track`：H3 只负责画面与非对白环境声，独立 TTS 是唯一对白事实源；TTS 缺失时要明确标记降级或阻止交付，不能静默改用 H3 人声。

### 2. 电话场景抢台词：计划时间不等于音频实际时间

历史 `cuesFromShots()` 对同镜多句按镜头总时长均分，`buildMixInput()` 只把 `startSec` 换成 `adelay`，所以样片出现了覆盖下一句的情况。首轮修复在交付执行器用 `ffprobe` 读取每条音频的实际时长，按实际时长连续安排对白，并将结果同步到混音、字幕和 manifest；超出镜头窗口或显式重叠会阻断质量状态，不截台词也不静默变速。

另外，旧版单字符串 `shot.dialogue` 在多角色镜头中只能走回落链，无法可靠表达电话两端的说话人。电话场景若把两个人的台词塞进一个镜头，模型和 TTS 都没有足够的结构信息来保证轮次。

结论：对白必须改成**显式说话人 + 非重叠时间窗**的时间轴事实。默认规则是一镜一位主动说话人；电话场景通过交叉剪辑拆成两个镜头。只有用户明确标记 `overlap: true` 且通过人工复核，才允许重叠对白。

### 3. 音画不同步：默认路径没有口型驱动

独立 TTS 轨道只改变声音，不会改变已经生成的视频嘴型；当前 `07-lipsync` 明确是实验性、默认不在流水线，且失败会回落原片段。因此“独立配音 + H3 I2VA”只能保证台词时间轴，不能承诺嘴型同步。

H3 本身可以走 `video_h3_talk`（TTS 驱动的 H3 片段），但当前流水线没有把 `TTS_TEXT`、`TTS_SPEAKER`、`TTS_VOICE_DESIGN` 注入该模板，也没有处理一个镜头多位说话人的拆分，所以这条能力尚未真正接入。

## 整改方案

### P0：先固定声音事实源与对白时间轴

1. **已完成首轮**：提示词编译输入加入项目 `audioMode`。独立对白模式下，H3 视频提示词不生成 `<d>` 台词块；原声模式下才允许 H3 承载对白。
2. 在 `video_h3_talk` 适配器中补齐 TTS 参数，并只对“单镜单主动说话人”的镜头启用。多角色电话场景先按镜头拆分，不把两个说话人塞进一个 H3 Talk 请求。
3. **已完成首轮**：交付执行器用 `ffprobe` 读取实际时长，按实际时长生成 `startSec/endSec`，并同步字幕和 assembly manifest；不执行隐式变速或裁切。
4. **已完成首轮**：交付前阻止同镜对白重叠和超出镜头窗口，质量状态为 `blocked`。
5. **已完成首轮**：独立配音缺失写入 manifest 与前端质量状态；允许生成可播放的降级预览，但不再把它标成质量通过。

### P1：把口型同步变成明确的生产选择

- 对单说话人镜头，优先验证 H3 Talk（画面、TTS、嘴型一次生成）与独立 TTS + `video_lipsync` 两条路线，使用同一关键帧、同一台词、同一角色音色做 A/B。
- 对多说话人镜头，先拆镜；不以“一个片段里让 H3 猜轮次”作为默认方案。
- 对口型失败继续允许回落，但回落必须在镜头和成片状态里显示“口型未处理”，不能把它显示成完整同步。

### P2：前端接上后端真实状态

视频·后期工作区需要同时展示音频阶段和成片阶段的事实：

- 当前声音路线（独立对白 / H3 原声 / H3 Talk / 口型后处理）；
- 每个镜头的说话人、VoiceProfile、TTS 产物、计划时长与实际时长；
- 重叠、超时、缺音色、缺 TTS、口型回落等 QC 结果；
- 成片按钮应读取服务端 QC 门禁，展示“可合成 / 缺少对白 / 仅降级预览”等明确状态；
- 预览仍只展示剧情、分镜和成片内容。模型提示词编译细节继续留在后端日志和 manifest，不进入用户界面。

## 最小真机验收场景

固定一个 2 镜电话场景：镜头 A 只有角色甲说一句，镜头 B 只有角色乙回一句；两角色各再追加一条跨镜台词。验收必须同时保存源视频、TTS 文件、最终成片、SRT、assembly manifest 和 QC 报告。

1. 角色甲的四条可比音频声纹稳定，角色乙与甲可区分；不能只凭“听起来像”判断，至少记录响度、时长和基础声纹指标。
2. A/B 台词在波形和字幕时间轴上不重叠；无电话争吵标记时不得出现同一时刻两条人声。
3. 实际 TTS 时长、SRT、成片时间轴三者一致；超出镜头窗口时必须被阻断或明确降级。
4. H3 Talk 与独立 TTS + lipsync 各跑一版，人工检查嘴型；未启用口型的独立 TTS 版本必须明确显示“音频已替换、口型未处理”。
5. 刷新前端、重启网关后，声音路线、Cue 状态、QC 结果和成片 manifest 保持一致。

## 本轮不做的事

暂不更换 MiniMax H3、Qwen3-TTS 或引入新的第三方口型模型；不把任何外部工作流未经 A/B 验收直接写成默认路线。先把单一声音事实源、实际时间轴和可见 QC 做实，再比较模型和工作流。
