## 1. 接入与鉴权

- 开放平台域名：`https://openapi.liblibai.cloud`（不能直接打开，必须带密钥访问）
- 密钥两段：`AccessKey`（访问凭证，长度约 20–30 位）+ `SecretKey`（签名密钥，长度约 30 位以上）
- 每次请求在**查询字符串**里固定携带 4 个参数：

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| `AccessKey` | 是 | 访问凭证 |
| `Signature` | 是 | 按下方算法算出的签名 |
| `Timestamp` | 是 | 生成签名时的**毫秒**时间戳，整数字符串，**有效期 5 分钟** |
| `SignatureNonce` | 是 | 随机字符串，防重放 |

- 签名算法（三步）：
  1. 拼原文：`URL路径 + "&" + 毫秒时间戳 + "&" + 随机字符串`（URL 路径形如 `/api/genImg`，不含域名与查询串）
  2. `hmacSha1(原文, SecretKey)`
  3. 转 **URL-safe base64**，且**不补全位数**

> 对我们的意义：这是「每请求现算签名」的模式，与 Bearer Token 不同。`gateway-api-benchmark.md` §6.6
> 设计的 `auth.mode: hmac` 就是照这个形状留的位。

## 2. 计费与配额

**计费不是固定单价**，单次生图任务的积分消耗与以下因子相关：

- 选用的模型
- 采样步数 `steps`
- 采样方法 `sampler`（**SDE 系列会产生额外消耗**）
- 生成图片的宽、高
- 生成张数
- 重绘幅度 `denoisingStrength`
- 高分辨率修复的重绘步数与重绘幅度
- Controlnet 数量

**配额**：

| 项 | 默认值 |
| --- | --- |
| 生图任务并发数 | **5**（指同时可进行的生图任务数） |
| 提交生图任务接口 QPS | **1 次/秒** |
| 查询生图结果接口 QPS | **无限制** |

> 官方给出的 QPS 估算口径：`每天预计生图张数 / 24h / 60m / 60s`。
> 对我们的意义：我们单卡 `concurrency: 1` 是硬件约束，对方 5 是商业配额；两者都该写进契约，
> 但**性质不同**——他们可以随时调，我们不能。

## 3. 能力清单（按原文档章节）

对方 API 面共 14 个模块。**提交任务 → 轮询查询**是统一范式，查询接口都是独立端点。

| 模块 | 覆盖的能力 |
| --- | --- |
| 星流 Star-3 Alpha | 文生图、图生图、查询结果、参数模板预设（`templateUuid`）、ComfyUI 接入星流 API |
| LiblibAI 自定义模型 | 查询模型版本、文生图、图生图、查询结果；参数含 `additionalNetwork`（LoRA）、`hiResFixInfo`（高分辨率修复）、蒙版重绘、Controlnet；生图/审核双状态机；参数模板预设 |
| F.1 Kontext | 文生图、**图生图（指令编辑 & 多图参考）**、查询结果 |
| 智能算法 IMG1 | 生图、**局部重绘**、查询结果 |
| 模型选择 | Checkpoint、LoRA、Textual Inversion（负向提示词）、VAE、采样方法、放大算法模型的可选清单 |
| ComfyUI 工作流 | 工作流生图、查询结果、部分工作流推荐、**个人工作流调用方法**、工作流调用费用 |
| libDream & libEdit | libDream 文生图、libEdit 指令编辑 & 智能参考、libEditV2、libdream 4.0、Libdream 4.5、查询结果 |
| 可灵 | 文生视频、图生视频、**多图参考**、查询结果 |
| Kling Omni-Video V1 | 接口定义、参数定义、返回值、查询结果 |
| Qwen Image | 文生图、查询结果 |
| 其它 | 生图完整 demo、错误码汇总 |

> 对我们的意义：`gateway-api-benchmark.md` §5 的逐项对照就是从这张清单展开的。
> 结论是我们**能力面覆盖度不低**（尤其 ComfyUI 工作流直调、个人工作流这两条我们本来就有），
> 真正的结构性缺口是模型生态、通用自然语言指令编辑（**注：Qwen-Image 2.1 接入后这条已大幅缓解**）与内容审核。

## 4. 状态机

**生图状态 `generateStatus`**

| 值 | 含义 | 备注 |
| --- | --- | --- |
| 1 | 等待执行 | |
| 2 | 执行中 | |
| 3 | 已生图 | |
| 4 | 审核中 | |
| 5 | 成功 | |
| 6 | 失败 | |
| 7 | 超时 | 任务创建 **30 分钟**后仍无执行结果即计入 timeout，并**解冻积分** |

**审核状态 `auditStatus`**

| 值 | 含义 |
| --- | --- |
| 1 | 待审核 |
| 2 | 审核中 |
| 3 | 审核通过 |
| 4 | 审核拦截 |
| 5 | 审核失败 |

> 对我们的意义：① 「已生图」与「成功」是两个状态，中间夹着审核 —— 我们的 `Artifact` 已预留
> `auditStatus` 字段但没有实现体；② **超时自动解冻积分**是很好的契约设计，我们的队列超时
> 目前只是抛错，没有「退还产能」的语义（我们是本地算力，等价物是释放 GPU 与标记任务终态）。

## 5. 错误码

| 码 | 含义 | 备注 |
| --- | --- | --- |
| 401 | 签名验证失败 | |
| 403 | 访问拒绝 | 未开通 API 权益，或账户 API 积分不足 |
| 429 | 请求太多 | QPS 超限（提交接口限 1 次/秒） |
| 100000 | 参数无效 | 通用参数校验失败 |
| 100010 | AccessKey 过期 | API 商业化权益已过期 |
| 100020 | 用户不存在 | |
| 100021 | 用户积分不足 | |
| 100030 | 图片地址无法访问或超出大小限制 | **图片不能大于 10M** |
| 100031 | 图片包含违规内容 | 图片需先过第三方审核，要求给审核服务方加白 |
| 100032 | 图片下载失败 | 网络问题；官方建议改用其文件上传接口 |
| 100050 | 生图参数未通过完整度校验 | **模板 / Checkpoint / LoRA / Controlnet 必须同一底模** |
| 100051 | 生图任务不存在 | |
| 100052 | 提示词含敏感内容 | 包括 `prompt`、`negativePrompt` 等 |
| 100053 | 模型不在提供的列表内 | 必须从平台的 Checkpoint / LoRA / VAE / Controlnet 清单里选 |

> 对我们的意义：`100050`（模板与权重必须同底模）和 `100053`（模型必须在清单内）这两条，
> 正是我们用 `{{TOKEN}}` 白名单 + `renderTemplate` 缺参早失败 + `/api/providers` 枚举可选模型
> 在本地等价实现的东西。`100030` 的 10M 图片上限我们没有对应限制（本地素材不走公网），属我们的优势项。
