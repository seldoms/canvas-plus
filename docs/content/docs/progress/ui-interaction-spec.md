# 交互规范（UI 铁律 + 验收铁律）

> 这份文档存在的理由：**产品负责人的原话** ——
> 「我认为这些东西只要是**正常的人类视角去使用一次**，都应该会有所察觉的。为什么你这边没有察觉出来？
>  是不是前期的 **PRD 文档写得不够完善**？」
>
> 他说对了两件事：
> 1. 这些（预览点不开、归档找不到、预览窗铺满屏、模型列表样式不统一）**确实是用一次就能发现的**；
> 2. 227 行的 `prd.md` 写的是**产品能力与架构**，**交互细则一条都没有** —— 光靠它推不出"用起来该是什么样"。
>
> **但不能把锅全给 PRD。** 真正的根因是验收方式：
> 我们一直在**证明"我改的那一处生效"**（按钮点了、接口返回了、`tsc` 0 错、截图贴了），
> **从来没有一次是"像个用户那样，从进页面到做完一件事，把这条动线走完"**。
> → **验收的是"功能实现"，不是"动线可用"。** 这是本文件第 0 条要根治的东西。

---

## 0. 验收铁律（最高优先级，先于一切）

### 0.1 每轮交付必须"人类视角走一遍完整动线"

- **不许**只做"逐点验证"（点一下按钮看有没有反应 = 不算验收）。
- **必须**：**从"一个不懂技术的人打开页面"开始，把这条动线走到底**，并回答：
  1. 我**一眼看得到**该点的东西吗？（找不到入口 = 不合格，无论功能多正常）
  2. 我**点下去**会发生什么？符合直觉吗？
  3. **做错了能退回来**吗？
  4. **看得到结果**吗？（有缩略图却看不到大图、有产物却下不了 —— 不合格）
  5. 我**做第二遍、第三遍**顺不顺（连续发任务、批量操作）？
- **报告里必须有一段"用户视角实录"**（不是 DOM 证据堆砌，是"我进去 → 我点了 → 我看到"的白话叙述）；
  DOM/接口证据**只是佐证，不能替代**这段叙述。
- ⚠️ **"截图贴了"不等于"看过了"**。截图只证明"当时画面上有这东西"，不证明"用户能发现它、用得顺"。
- ⚠️ **子代理报"CDP 真点成功"也不等于动线可用** —— 它证明的是"脚本点到了元素"，
  不证明"人一眼能找到这个元素"。**必须追问**："入口在视觉上显眼吗？"

### 0.2 发现一处 → 全站排查同类

- 任何一条 UI 铁律被违反，**同一轮内必须全站排查**同类位置并列出清单（改了哪些、还剩哪些）。
- **禁止**"发现一处只改一处"。

### 0.3 效果类/观感类结论交给人

- 画面像不像本人、口型对不对、字幕观感、内容是否单薄 —— **机器判不准**，
  直接把**成片 + 对比图**发给产品负责人，结论交给他，**不要自己下"达标"的结论**。

---

## 1. 预览铁律

1. **只要有缩略图，点开必须能看** —— 不许存在"看得见、点不开"。**这条是硬性的**。
2. **预览一律站内弹窗，禁止跳新页 / 禁止下载代替预览**。
3. **预览窗必须响应式**：**小播放窗口、按比例自适应**，**不许铺满整屏**。
   - 长边留边距，画面按原始宽高比完整显示（contain，不裁不拉）。
4. **弹窗内方向键 `← → ↑ ↓` 切换同一组素材**（`↑↓` 是 `←→` 的别名）；`Esc` 关闭；首尾不循环。
   - **分组粒度 = 同一个项目 / 同一个栏目（环节）内输出的素材**（不是全站一个大组、也不是只能单张）。
5. **关闭方式**：弹窗**不留 × 点**，**点任意处关闭**，关闭后**回到顶部**。
6. **图片 / 视频 / 音频都要能预览**（视频用带控件的播放器，音频用播放条）；**类型不同也要在同一组里能前后切**。
7. **取不到图时给明确占位 + 可读原因**（不许渲染成 1×1 空白骗人）。

---

## 2. 归档 / 删除铁律

1. **生产动线（工作台、流水线各环节、任务页）都要能看到「归档」入口，且入口要在卡片上、一眼可见** ——
   不许"藏在点开记录后的下半屏"。
2. **归档后列表上必须有可见状态**（打标"已归档"或从主列表移出，二者择一并保持一致）——
   **不许点了归档列表毫无变化**。
3. **归档可逆**：操作后给「撤销」；另提供「恢复」入口（不能只有 UI 气泡那一条路能撤销）。
4. **彻底删除只在「我的资产」**；被引用默认拒删；删除走「搬回收区」可回滚。
5. **归档目标的来源**：**从该次任务的产物取**（job 的产物清单），
   **不要依赖记录里图形对象的字段**（历史记录缺 `jobIds`/`artifactUrl`，会导致入口直接不渲染）。

---

## 3. 模型 / 能力列表铁律

1. **按基座（base）分组**：**组头只写一次基座名，组内只写能力名**（不重复基座）。
2. **归组顺序 = 接口返回顺序**；**禁止硬编码基座名单**（清单/配置必须与后端接口联动动态获取）。
3. **云端项加 ☁️**：整组都是云端 → ☁️ 提到**组头**；混合 → ☁️ 落到**各条**。
4. **全中文、名称短到能显示全、禁缩写**。
5. 已有参考实现：`web/src/components/model-picker.tsx`、`web/src/components/layout/config-model-registry.tsx`。
   **别处要统一到这套**，能包装共享件就包装，**不许复制样式第 N 份**。

---

## 4. 文案铁律

1. **禁解释性小字**：按钮/字段的文字**自解释即可**，不要在每个控件下面加一句解释。
2. 中英双语（i18n 两个语言文件**同步**，不留死键）。
3. 报错要说人话：**"该模型画面上限 1920×1088（2,088,960 像素），当前 2048×2048 超了"**
   而不是把下游的 `execution_error` 直接抛给用户。

---

## 5. 布局铁律

1. **禁跟屏留白**（不要为了撑满而拉大间距）。
2. **列表优先时间线式**。
3. **不堆选项**：能自动判断的不让用户选；必须让用户定的才给选项。
4. 面板可隐藏 / 表单紧凑。
5. 素材与产物预览**一律站内弹窗**。

---

## 6. 任务与记录铁律

1. **点「开始生成」当帧就在列表里落一条**（不等结果）；点进去能看**当次参数快照 + 本次结果**，
   **与当前表单互不污染**（可以无脑连发新任务）。
2. **生成中可取消**；**已完成可归档**；**归档可逆**；**彻底删除只在「我的资产」**。
3. **记录必须服务端持久化**（换设备、清缓存都还在）—— 不许只存浏览器本地。
4. **提交即入队、不锁界面**；可见状态 + 真实进度百分比。
5. **两个工作台（生图 / 视频）共用同一套逻辑**（组件 + 业务逻辑都共用，不各写一套）。

---

## 7. 尺寸 / 生成参数铁律

1. **能力元数据（尺寸档 / 时长档 / 像素上限）是服务端注册表的唯一持有者**，
   **取自调研报告**，禁止前端硬编码、禁止自己推导拍脑袋。
2. **画布尺寸跟随输入图**（有输入图时以图的真实宽高为准，不信前端传的尺寸）。
3. **超限要自适应**（方向对就自动压/放到合法档），**不要报错拒绝**；
   但**必须留痕**（记进该次任务，可查），**不许静默改参数**。
4. **兜底**：连合法档都找不到 → 回落**可读的拒绝**，**绝不静默放过**。

---

## 8. 自检清单（每轮交付前逐条过）

```
□ 我以"用户身份"完整走过这条动线了吗？报告里有白话实录吗？
□ 入口一眼可见吗？（不是"能点到"，是"能找到"）
□ 有缩略图的地方，点开都能看吗？
□ 预览窗是响应式小窗吗？方向键能切同组素材吗？
□ 该有归档的地方都有吗？归档后列表有可见状态吗？
□ 模型列表按基座分组了吗？组头只写一次吗？
□ 有没有解释性小字？中英双语都同步了吗？
□ 同类问题全站排查过了吗？剩下哪些？
□ 效果类结论我是不是该直接发给产品负责人，而不是自己判"达标"？
```
